## MCP decision

Differences between the knowledge in the npm release 0.1.0 and a build from `main`:

- the version labels (0.9.0 → 0.9.1);
- the compatibility facts (Firefox is now tested);
- the measured bundle sizes (about 1 KB larger per bundle in 0.9.1);
- one example. Example 6 ("Element size") in 0.1.0 uses `round(var(--w) / 1px)`, which Firefox cannot evaluate. The source uses the cross-engine form.

The registry entries and the API are the same.

**Decision: no republish now.** 0.1.0 gives correct syntax for 0.9.1, so this is not a release blocker. The source on `main` is already the update, and `packages/mcp` tests pass with it.

The version stays 0.1.0 on `main`, on purpose. The site reads `packages/mcp/package.json`. A version that is not on npm makes the MCP page and the homepage say "not on npm yet" at the next deploy.

When an MCP release is wanted (recommended for the example and size fixes):

1. Set `packages/mcp/package.json` `version` to `0.1.1`, then run `npm test` in `packages/mcp`.
2. The owner publishes from `packages/mcp`. A 2FA approval is necessary.
3. After `npm view @reactivecss/mcp@0.1.1` returns the version, add `0.1.1` to `mcp.npmVersions` in `site/config/distribution.json`. Then deploy the site.

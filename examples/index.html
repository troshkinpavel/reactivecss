Reactive CSS

Reactive functions and state-transition selectors for plain CSS. Every effect below is written in CSS and run by the library: the page script only adds elements and changes variables.

A. Random particles random() · pick() · live()

  background: pick(#ff5d73, #ffb84d, #4dd4ac, …);

D. Mouse tracking mouse()

.pad { --mx: mouse(x, local); --my: mouse(y, local); }
.pad .dot { translate: var(--mx) var(--my); }

local = CSS pixels from the top-left corner of the element that declares it (border box, here the pad). The default, viewport, is clientX/clientY.

E. Visibility visible()

.reveal {

}

F. Event-driven values on()

.tile {
  rotate: on(pointerenter, random(-14deg, 14deg));
  background-color: on(click, pick(#ff5d73, #ffb84d, …));
}

Hover a tile to re-roll its rotation, click it to re-pick its color.

G. Tabs state() · on: · set() · :nth-var()

.tabs { --active: state(1); }
.tab { on: click(set(--active, sibling-index())); }   /* buttons */
.choice input { bind: --active; }                    /* or radios */
.tab:nth-var(--active) { color: var(--accent); }
.panel { display: none; }
.panel:nth-var(--active) { display: block; }
Overview: each component owns its own --active.
Settings: the buttons and the panels are two sibling groups that share the nearest state.
Activity: no script on this page handles these clicks.
Section
Overview: a native radio group bound with bind: --active.
Settings: arrow keys move between the options; the checked state is announced.
Activity: the panels follow the same state through :nth-var().

Accessibility. The first instance is visual switching only: plain buttons, not an ARIA tabs widget (no arrow-key navigation, no aria-selected, no panel association), because CSS cannot update ARIA attributes or move focus. The second instance uses a native radio group with bind: --active: keyboard navigation and the selected state come from HTML. It is a radio group, not a tabs widget. A full tabs pattern needs JavaScript.

I. Counters increment() · decrement() · :when()

.counter { --count: state(0); }
.inc { on: click(increment(--count)); }
.dec { on: click(decrement(--count)); }
.reset { on: click(set(--count, 0)); }
output { counter-reset: n var(--count); }
output::before { content: counter(n); }
.counter:when(--count >= 10) output { color: green; }

content: var(--count) cannot print a number in CSS; a CSS counter can. Accessibility. Generated content is read inconsistently by screen readers, and changes are not announced (no live region). Show values that matter in real text.

J. Toggle switch when() for values and strings

.switch-row { --on: state(false); }
.switch { bind: --on; appearance: none;   /* <input type="checkbox" role="switch"> */
  background: … when(--on, 21px, 3px) …, when(--on, var(--accent), var(--line)); }
.switch-label::after { content: when(--on, "On", "Off"); }

Accessibility. A native checkbox with role="switch": focus, Space and the on/off state come from HTML. The state is bound with bind:, so the rest of the page can react to it.

M. Counter history previous() · direction() · :changed()

.history { --count: state(0); --last: previous(--count); }
.history:changed(--count):when(direction(--count) > 0) .num {
  animation: rise 300ms; }
.history:changed(--count):when(direction(--count) < 0) .num {
  animation: fall 300ms; }

Repeated clicks restart the animation: :changed() follows each real change and clears when the animation ends.

N. Checkbox binding bind: on a checkbox

.settings { --enabled: state(false); }
input[type=checkbox] { bind: --enabled; }
.status { opacity: when(--enabled, 1, 0.4); }

when(--enabled, …) with a boolean state and static values compiles to native CSS if() where supported.

O. Keyboard key(Escape, …)

.dialog-state { --open: state(false);
  on: key(Escape, set(--open, false)); }
.opener { on: click(toggle(--open)); }
.sheet { display: when(--open, block, none); }
Press Escape while focus is inside this panel.

Accessibility. Not a modal dialog: no focus trap, no focus return, no ARIA. For real dialogs use the native <dialog> element (Escape closes it natively).

Q. Typed property typed() (experimental)

:root { --angle: typed(0deg); }   /* registers <angle> */
.face { --angle: calc(var(--turn) * 90deg);
  background: conic-gradient(from var(--angle), …);
  transition: --angle 600ms; }

Without the registration, a custom property cannot be transitioned: the gradient would jump.

S. Element geometry element(width)

.geo { --w: element(width); width: var(--size); }
.geo .label { font-size: clamp(12px, calc(var(--w) / 18), 28px); }
.geo .bar { width: calc(var(--w) / 2); }
.geo .px { counter-reset: w calc(var(--w) / 1px); }
Measured

Runtime. One shared ResizeObserver, border-box size, written in the next frame. Drag the corner (mouse) or use the buttons (keyboard). Reading the width into the element's own width would loop; that is detected and frozen with a warning. To size children by a container natively, prefer container query units (cqw).

T. Greetings attr(), pick(split())

.greeting { --message: state(attr(data-message, "Hello!")); }
.greeting output::after { content: var(--message); }
.greeting .choice  { on: click(set(--message, attr(data-message))); }
.greeting .shuffle { on: click(set(--message, pick(split(attr(data-greetings), "|")))); }

Runtime, at event time. Each value comes from an attribute of the clicked button, or of the state owner at start. Attribute values are only ever text: they are escaped into one CSS string. Plain content: attr(…) elsewhere stays the browser's own.

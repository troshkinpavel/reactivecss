## Why use it
Language models learn from whatever Reactive CSS they saw in training, which is often an older API. Without help, an agent may write `on: click(toggle(--open))` instead of `:on(click)`, or invent functions the runtime doesn't have.

The MCP server gives the agent the current documentation and a validator, so it can check its own output before showing it to you.

- **Current syntax.** Answers come from the 0.9.0 reference, not from training data.
- **Checked code.** The agent can validate a stylesheet with the library's own compiler, and fix what the runtime would reject.
- **Migration help.** Older declarations such as `on:`, `bind:` and `text:` are mapped to their 0.9.0 forms.
- **Smaller bundles.** The agent can recommend Full, Compact or a Custom bundle from the features your CSS uses.

## [1] Install
<NpmState pkg="mcp" published={false}>

Build the server from the repository. It needs Node.js 22 or later. The server bundles the library's compiler, so build the library first:

```bash terminal
git clone https://github.com/troshkinpavel/reactivecss.git
cd reactivecss
npm install && npm run build
cd packages/mcp
npm install && npm run build
```

The server is `packages/mcp/dist/index.js`.

</NpmState>
<NpmState pkg="mcp" published>

Nothing to install: clients start the server with `npx -y @reactivecss/mcp`. It needs Node.js 22 or later.

To run a copy installed in your project instead, add it as a dev dependency and use `npx -p @reactivecss/mcp reactivecss-mcp` as the command. Keep the `-p`: npx then runs your installed copy, and never looks up the unscoped name `reactivecss-mcp` on npm, which this project does not own.

```bash terminal
npm install --save-dev @reactivecss/mcp
```

</NpmState>

## [2] Connect your client
Most MCP clients read a JSON configuration that names the server and the command that starts it.

<NpmState pkg="mcp" published={false}>

Replace the path with the absolute path to `dist/index.js` on your machine.

```json mcp.json
{
  "mcpServers": {
    "reactivecss": {
      "command": "node",
      "args": ["/absolute/path/to/packages/mcp/dist/index.js"]
    }
  }
}
```

In Claude Code, add it from the terminal:

```bash terminal
claude mcp add reactivecss -- node /absolute/path/to/packages/mcp/dist/index.js
```

</NpmState>

## [3] Check that it works
Ask your agent a question only the current docs can answer, such as how to read the click position in an event rule. A connected agent should look it up and answer with `set(event(client-x))` inside a `:on(click)` rule, stored in a length state such as `state(0px)`, citing the 0.9.0 reference.

## What it provides
Everything is read-only and offline: the server reads no files of yours, opens no network connections and runs no code from its input.

<Facts>
  <Fact label="Tools">7: API lookup, documentation search, examples, validation, feature analysis, bundle advice and migration</Fact>
  <Fact label="Resources">8: reference documents the client can read directly</Fact>
  <Fact label="Prompts">4: ready-made tasks such as migrating a stylesheet</Fact>
</Facts>

### Tools
Actions the agent calls with arguments, for example "look up `increment()`" or "validate this stylesheet": `get_api_reference`, `search_docs`, `get_example`, `validate_css`, `analyze_features`, `suggest_bundle` and `migrate_css`. Their parameters are in the package README.

### Resources
Read-only documents the client can attach to a conversation: the API reference, the bundle features and their dependencies, the migration guide, compatibility, experimental APIs and common mistakes.

### Prompts
Templates your client can offer as commands: `create_reactive_component`, `migrate_to_v09`, `review_reactive_css` and `optimize_reactive_bundle`. Each one tells the agent which tools to call and to validate the result.

## Example: validating agent output
An agent asked for a disclosure menu first produces older syntax. It calls `validate_css`, which reports the legacy declarations, and the agent rewrites them before replying.

```css menu.css
.nav {
  --open: state(false);
}
.nav button {
  on: click(toggle(--open));
  attr: aria-expanded var(--open);
}
```

<Callout kind="warning" title="Validation result">

Two warnings: `on:` (`MCP-legacy-on`) and `attr:` (`MCP-legacy-attr`) are 0.8 syntax. They still run in 0.9.0, but the current forms are `:on(click)` for the event and `--attr-aria-expanded` for the attribute.

</Callout>

```css menu.css
.nav {
  --open: state(false);
}
.nav button {
  --attr-aria-expanded: var(--open);
}
.nav button:on(click) {
  --open: toggle();
}
```

<Callout kind="outcome" title="Validated">

No errors or warnings. `suggest_bundle` recommends a custom bundle with `core`, `events` and `attributes`, and gives the `reactive-css build` command for it.

</Callout>

## Limits
- The server describes Reactive CSS. It doesn't run your page or see your DOM.
- Validation checks syntax and API usage, not visual results. Test in a browser.
- Answers target 0.9.0. They also apply to 0.9.1, which changed no syntax or API. Use the server version that matches your runtime.
